# ROFL 1.4 — release notes

Since `rofl-nb-1.3.2` (6882b3a, 2026-10-21): PRs #78–#86. Every line names the
PR that made it; what an agent must do differently comes first. The 1.3 notes
are kept in docs/releases/1.3.md, and their known gaps stand: nothing here
touches them.

## What an agent must do differently

1. **Ask again: the world is kept.** `rofl ask`, `why`, `whynot` and `excise`
   keep the world they evaluated under `$XDG_CACHE_HOME/rofl/worlds` (else
   `~/.cache/rofl/worlds`), named by its walls, its files, the environment the
   engine reads and the engine binary. The next question over the same files,
   in a new process, is answered from disk without evaluating. Nothing to turn
   on. `rofl load`, `rofl serve`, `npm test` and every other gate never read
   nor write it (#83, docs/cli.md *A world kept on disk*).
2. **An edited file goes by delta.** When a file the kept world was computed
   from changed, came or went, the run opens the kept world, takes the base
   facts of the changed and gone files out in one pass, adds the new ones,
   answers, and keeps the world again; a changed `.js`/`.ts` is scanned again
   alone. It says so in one line on stderr (#86):

       the kept world took 1 file by delta: db.rofl (35 facts out, 409 overdeleted or derived again; opened and taken in 201 ms, kept again in 12 ms, 9367080 bytes written)

   It evaluates whole instead, with the reason after `not by delta:`, when the
   rules changed (a changed file holds a rule, or a gone file held one), the
   world is a `.rofl.md` or uses `--below`, a scanner ran in another
   directory, a changed file is neither named nor read by a scanner, or the
   engine refuses the delta. The line has the shape

       the kept world <path> is stale: <what changed>; computed anew, not by delta: <why>

   The answer is the fresh evaluation's either way.
3. **`--kept F` names the kept world yourself, under a stricter rule**:
   computed once, each question a new process that does not evaluate again,
   and refused, never recomputed, once stale (exit 2):

       world.vol is stale: rules/x.rofl changed since it was kept; run again with --anew to compute it anew

   `--anew` computes it again from its files and keeps it over the old. A run
   that names no files takes them from F; a run that names files must name the
   ones F was kept from. A file at F cut short, changed after it was written or
   not a kept world is refused (exit 2): the volume ends in a checksum over its
   bytes (#83).
4. **One knob sizes the cache: `ROFL_CACHE_GB`** (default 50), a hard cap.
   Older worlds are evicted first, least recently used; nothing is written
   below 5 GB of free disk; a world larger than the cap stops evaluating
   there, is kept as it stood and answers partially (exit 5); a larger cap
   goes on from where it stopped (the disk wall, below). A world whose given
   facts alone pass the cap is answered and not kept, said on stderr:

       the world is not kept: the world is larger than 1.00 GB, the most it may take: the cap is 1.00 GB (ROFL_CACHE_GB)

   Sizes are printed in KB, MB or GB (#84). The cap counts every file in the
   directory, and a run sweeps what writers killed mid-write left before it
   writes (#86).
5. **Scan JS code again, and rewrite a rule that reads `ast_node` with four
   arguments.** A JS node id is now its place in the tree (the file's prefix
   and a hash of parent id and step), not its place in the walk, and the line
   left `ast_node`: the scanner prints `ast_node(Id, Kind, File)` and
   `ast_line(Id, Line)`. A `code.rofl` written by `npm run scan` of 1.3 carries
   the old shape and old ids; scan again. Neither mismatch is refused: a
   premise of one arity over facts of another matches nothing, so an old scan
   or an old rule answers empty, silently. `ast_child` keeps its index (#85).
   Empty `~/.cache/rofl/scans` (or `$XDG_CACHE_HOME/rofl/scans`) after
   upgrading: see *Known gaps*.

## What changed since 1.3.2

- **#78 `npm test` keeps answers by hash.** Each world's answer is kept per
  engine under the hash of everything it is a function of (the harness, the
  TypeScript sources or the Rust binary by its bytes, boot, options, node's
  version, every loaded file); the golden is still compared on every run, and
  a red world's kept answers are dropped and its state written to
  `.cache/rofl/reds/`. `scripts/keep_check.ts` turns each key part red when it
  is left out. Bless no longer runs TypeScript on the Rust-only worlds.
- **#79 Harness.** CI reuses the keep on pull requests; a push to main and
  `rofl-nb-*` tags run cold. A killed run kills everything below it (pool
  workers, their `rofl` children, Chrome) and removes browser profiles; orphaned
  `wb-chrome-*` browsers are reaped. A world whose file is gone or unreadable is
  a sentence (`FAIL <world>: it loads <file>, which is not there`), and bless
  refuses before evaluating.
- **#80 A sentence with `a/b` that is not read is said once, as written.**
  Both readers (`scripts/read_md.ts`, `rust/rofl/src/md/reader.rs`) reported
  it twice, each copy cut at the slash (`scanners/gh_actions.py` as
  "scanners.py" and "gh_actions.py"). A head containing `a/b` is not learned
  from by a notebook's book.
- **#81 The Rust snapshot is written and read without serde Values.** Same
  text byte for byte in 598 of 607 worlds (8 differ only in the order of
  `ghosts`, which varies run to run on main too; the 607th is the planted-fault
  census), same format. The reader takes a fact's fields in any order; before,
  it refused every snapshot the Rust engine wrote and parsed the file again.
- **#82 CLAUDE.md states the goal** (the engine for agents, the notebook for
  people, scale part of the goal) and the five questions every brief answers.
- **#83 A world kept on disk**: items 1, 3 and 4 above. Also fixed: after a
  volume or kept image was opened, a negation unfolded at a call read a hole
  as an absence (`rofl serve`'s `volumePath` and `keptPath` too).
  `examples/fork_layers.rs` builds again.
- **#84 Retraction refuses a set it would take as one fact.**
  `Eval::retract_delta` took only the first fact of a set and kept the
  consequences of the rest; it now refuses with `the delta takes one fact at
  a time, and X was given beside Y`. A negating rule is stopped only by a base
  fact of its own book (`shape_verdict[audit]` derived beside a base
  `shape_verdict[main]` had refused every delta).
- **#85 A JS node id is its place in the tree; the line is its own fact**:
  item 5 above. About 370 premises of `rules/js-*.rofl` were rewritten; the
  readers, renderer, phrases, playground and the committed scans in
  `examples/checks/*-facts.rofl` follow.
- **#86 A kept world takes an edited file by delta**: item 2 above. A set of
  base facts goes in one DRed pass (`Eval::retract_set`) from a citer index
  kept by every firing and saved with the volume; a tree-closure edge that
  goes rebuilds only the trees it is in.
- **The disk wall** (w_disk_wall): a question verb's world stops where its
  volume would pass what `ROFL_CACHE_GB` gives it, with
  `hole($adhoc, disk_exhausted)`, is kept and answers partially; a larger cap
  goes on from the cut to the world a run under it from the start reaches,
  byte for byte (tests/disk.rs, tests/kept.rs, docs/cli.md).

## Format changes

- **The kept volume is `ROFL-VOLUME-3`** (1.3.2 wrote `ROFL-VOLUME-1`): it now
  carries the record of what the world was computed from and the citer index
  (#83, #86). A volume of an older format is not read: it is refused with
  `F: a volume of another format`, with `--kept F` as exit 2. A volume of the
  same format written by another build is refused too (`a volume of another
  build`; under `--kept F` it is stale, `the engine changed since it was
  kept`). Compute it again from its files (`--anew`). The worlds the question
  verbs keep by themselves are named by the engine binary, so a new binary
  never opens an old one; 1.3 kept none by itself.
- **The kept image is `ROFL-KEPT-4`** (1.3.2: `ROFL-KEPT-3`, #83); an older one
  is refused as `not a kept image of this build`.
- **The JS model's facts**: `ast_node(Id, Kind, File)` and `ast_line(Id, Line)`
  instead of `ast_node(Id, Kind, File, Line)`, and node ids by place in the
  tree (#85). A 1.3 scan under the 1.4 model loads and answers empty.
- **The snapshot (`--seed`, `rofl serve`) is unchanged** (#81).

## Install

Pick the VSIX for your platform (`rofl-1.4.0-<platform>.vsix`: linux-x64,
linux-arm64, darwin-x64, darwin-arm64, win32-x64), with VS Code 1.101+:

    code --install-extension rofl-1.4.0-darwin-arm64.vsix

The command line, with Node 22+: `npm install -g ./rofl-nb-1.4.0.tgz`. The
engine alone: `rofl-<platform>` (`rofl-win32-x64.exe` on Windows; chmod +x on
macOS and Linux). `SHA256SUMS` lists the sums. The VSIX is not published to
Open VSX (the release has no `OVSX_PAT`).

## Known gaps

- **A kept scan outlives its scanner** (f_a_kept_scan_outlives_its_scanner).
  The storeroom of scans (`~/.cache/rofl/scans`) is keyed by the directory,
  the command and the path, and stamped by what the scanner read, not by the
  scanner's own source, so a scan written by 1.3's JS scanner can be answered
  to 1.4 in the old shape (item 5). Empty that directory after upgrading;
  bless with `XDG_CACHE_HOME` set to an empty directory until it is fixed.
- **A kept world is written whole by each edit**
  (f_a_kept_world_is_written_whole_by_each_edit): the facts an edit touches
  stay flat with the world, its time does not (see *Numbers*). The volume also
  grows by edits, its dead ids kept. Wanted: a journal or overlay per edit,
  typed row keys, kept planner statistics.
- **A world cut at the disk cap and given a larger cap that is still too small**
  stops at that cap in a different place than a run given it from the start
  (f_a_cut_gone_on_from_and_cut_again_is_not_a_fresh_cut): the step wall's
  cuts were never equal there either. Raised enough to finish, it is the whole
  world byte for byte (w_disk_wall, docs/cli.md).
- **Not verified by #83**: the 17 sentence-form `.rofl.md` worlds kept, the
  5 GB floor (it needs a full disk), and whether a lattice world that widened
  is evaluated again on open.
- **`cargo test` is red on main** (f_cargo_test_is_red_in_three_tests_on_main,
  not looked into): `session` and `lattice_scale` (#86), and `demand_fixpoint`
  as #81 and #83 reported.
- **`rofl serve` answers no row for an `ask` by its last argument in worlds that
  tick or explain** where TypeScript answers one: 97 of 22 560 whycheck
  questions in 30 worlds (f_whycheck_asks_by_the_last_argument_and_serve_answers_nothing,
  found by #81, not made by it).
- **Snapshots of widening and narrowing worlds are not byte-stable**: the
  order of `ghosts` varies from run to run in 8 worlds; every reader orders by
  key (f_ghosts_come_out_in_an_order_that_varies).
- **Unexplained once**: on the owner's laptop, outputs came back with bit 0x10
  of one byte cleared, with this and older binaries; it may be the machine
  (f_a_state_came_back_with_one_bit_cleared). One cold run's minimax state
  differed once under load and was not reproduced
  (f_minimax_rust_state_differed_once_under_load).
- **A rename of a JS function moves its subtree's facts** (1 378 against 52
  with the 1.3 ids, #85), accepted by the owner.
