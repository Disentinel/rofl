# ROFL 1.2 — release notes

Since `rofl-nb-1.1.0` (5ba6b41, 2026-10-06): PRs #11–#20. Every line names the
PR that made it; what an agent must do differently comes first.

## What an agent must do differently

1. **One binary.** `rofl` (`rofl load`, `rofl serve`, ...) replaces the
   scattered `rofl-load` / `rofl-serve` / `rofl-eval`; CLAUDE.md's knob table
   is the whole agent-facing set, every other flag is an oracle in
   docs/knobs.md (#12).
2. **Notebooks run on Rust.** The VS Code extension and the kernel evaluate on
   the Rust engine by default (`rofl.engine`), every notebook now, not only the
   layered ones. Still on TypeScript: a run with `ROFL_NB_LIMIT` or
   `ROFL_NB_MEMORY` set, and a notebook with an `excise` line (#15, #18).
3. **Edit a `.rofl.md` only with `nb edit`.** `npm run nb -- edit F.rofl.md
   --cell N [--lang L]` (`rofl-nb edit` when installed) takes the cell on stdin
   and writes the file only if every cell reads back as meant. An editor's
   file tools on a notebook-typed file can shred it (#17).
4. **A refusal says why.** A stalled program names its negation or aggregate
   cycle; `whynot` names the file that was not loaded; the sentence form
   refuses what it used to drop silently (#13).
5. **A cut-short run names the limit**: the clock (`ROFL_NB_LIMIT` raises it),
   the heap (`ROFL_NB_MEMORY`), or the space limit, which no notebook setting
   raises (#18).

## New

- **Staged evaluation, first steps** (#11, plan in docs/staged-evaluation.md):
  a corpus ingested file by file by delta equals the whole world byte for byte
  (scripts/ingest_by_delta.ts); a question added to an evaluated cone costs its
  own delta (scripts/stage_by_asks.ts); an evaluated world is kept on disk and
  opens evaluated (`Session::keep` / `open_kept`, `rofl serve` keep/open).
- **Faster engine** (#20, Rust release, 20 files of vscode): a kept world
  opens in about 0.6 s (was 1.2 s); a kept lattice or sealed world opens
  evaluated; adding one file to an evaluated world costs about 0.35 s (was
  0.45 s): an aggregate rule withdraws only its own firings.
- **Retraction** takes the edb/authority rows only the retracted fact wrote, and
  a world records `evaluated_again(Request, Reason)` where a delta fell back to
  a full evaluation (#14).
- **JS model** (#19): object-pattern parameters and defaults
  (`({port = 80}) =>`, `const {PORT = 1343} = env`) bind;
  `parseInt`/`Number`/`parseFloat` keep their argument's value;
  `Object.assign(target, ...)` writes onto and returns its target; calls under
  `if (require.main === module)` / `!module.parent` give `arg_at` nothing.
- **CI publishes a release** from a `rofl-nb-<version>` tag once every gate is
  green: the `rofl` engine for five platforms, one VSIX per platform carrying
  its engine, the `rofl-nb` tgz, and SHA256SUMS.

## Install

Pick the VSIX for your platform (`rofl-0.3.0-<platform>.vsix`: linux-x64,
linux-arm64, darwin-x64, darwin-arm64, win32-x64), with VS Code 1.101+:

    code --install-extension rofl-0.3.0-darwin-arm64.vsix

The command line, with Node 22+: `npm install -g ./rofl-nb-1.2.0.tgz`. The
engine alone: `rofl-<platform>` (chmod +x on macOS and Linux).

## Known gaps

- `w_rust_default_backend` stays open: a clock or memory limit on a Rust
  notebook needs a deadline in `rofl serve`, and `excise` needs a forkable
  Rust world.
- The JS model reads no nested or rest pattern in a parameter, no lodash
  `assign`/`extend`, and no `Object.assign` alias exported across files.
