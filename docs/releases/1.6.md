# ROFL 1.6 — release notes

Since `rofl-nb-1.5.1` (25e7e74d, 2026-10-25): 86 pull requests, #128–#226.
Every line names the PRs that made it; what an agent must do differently comes
first. The 1.5 notes are kept in docs/releases/1.5.md, and their known gaps
stand except where a line here says one is closed. Some of 1.5.md's 1.5.1
section (an edit kept over the edit before it, a full pass keeping the
finished layer) was written there after the tag; it ships in 1.6.

## What an agent must do differently

1. **A world larger than memory stops and says so** (#178). Every `rofl`
   process watches its cgroup's limit or the machine's free memory; near it an
   evaluation stops with `hole($adhoc, memory_exhausted)`, a question verb
   answers partial (exit 5) and keeps nothing, and `rofl serve` answers
   `stopped: heap`. Read exit 5 as "short", never as a crash.
2. **A question verb evaluates only its cone** (#178, #186). `rofl ask`,
   `why`, `whynot` and `excise` run the rules their question needs and judge
   only the promises that cone reads; a notebook runs only what its lines ask
   (#154). 700 vscode files: 104 s and 3.4 GB → 49 s and 2.1 GB.
3. **`whynot` prints the nearest failure** (#184): one chain, the rule and
   premise that leave the fewest conditions unmet. The whole walk is
   `rofl whynot --all` (`rofl-nb --all`). A script that parsed the old walk
   must pass `--all`.
4. **oxc is the only JS scanner; Babel is gone** (#192, #199, #205, #207,
   #220, #221, #225). `npm run scan` runs `rust/tools/oxc_scan` (natively on
   the command line, compiled to wasm in the browser) into `[ast_oxc]`;
   `models/lang/js/oxc-roles.rofl` reads it into the roles of
   `models/lang/js/roles.rofl` (`[value]`, `[type]` over `[tree]`), and the JS
   model reads the roles for functions, values, scopes, control, members and
   keys, modules, guards and TS types. `npm run test:roles` checks each file's
   roles stand alone. **A scan written by 1.5's Babel scanner does not load
   into the 1.6 model: scan again.** A kept world rescanned keeps its ids over
   oxc (`scanners/oxc_inherit.ts`, #225). The peel ranks a relation by its
   name and its book: `r[a]` and `r[b]` are two relations to it (#220).
5. **The profile of an evaluation is a book** (#198, #200–#203, #206, #208).
   A rule reading a relation of the book `profile` gets, after the first run,
   what each rule and premise cost; `models/engine/profile.rofl` judges
   hypotheses over it, `models/engine/plan.rofl` plans the join order as a
   fixpoint, and the engine obeys a join order given as a fact.
   `npm run refine -- <files>` runs ask → reflect → refine → ask again; the
   agent's skill is `.claude/skills/refine-plan/SKILL.md`. Rust only.
6. **The detection report proposes all eight structures** (#210):
   `npm run structures` adds `ordered`, `sequence`, `span`, `equivalence` and
   `dag` beside `function`, `tree ... closure` and `alias`. The five new ones
   are detection only: no parser or engine path reads them yet.
7. **Adapters** (#141, #142, #144, #146): a book can be
   `roflenox://HOST/IDENTITY/BOOK`, signed on a Roflenox node and checked by
   the engine before it is read (a failed chain refuses it, exit 2); a `rofl`
   adapter can ask a world another process serves (`rofl serve FILE...`, also
   over `ssh`); `rofl adapter login ISSUER [CLIENT_ID]` signs a person in by
   OAuth 2.1 with PKCE, tokens in `~/.config/rofl/logins.json`, never in a
   fact; an `event_time` column arrives as one UTC instant with
   `instant(Text, Ms)` beside it.
8. **A notebook opens from GitHub in VS Code** (#189):
   **ROFL: Open notebook from GitHub…**, private repositories too.
9. **`rofl ask` and `rofl why` answer a corpus by volumes, by themselves**
   (#224). A world whose facts name two or more files, hold 32 MB or more and
   write `[surface]` is cut by file and dealt to a worker a core; stderr says
   `volumes: N files on K workers, ...`, and the volumes are kept beside the
   question's slot. vscode on 4 cores: 250 files 19 s against 50 s whole, 500
   files 32 s against 71 s, the answers byte for byte. Memory is not lower;
   `whynot`, `excise`, `--kept` and `rofl load` still evaluate whole
   (docs/cli.md, *A corpus larger than one heap*).
10. **The `[lifecycle]` world over the JS model** (#222): add
   `models/lang/js/lifecycle-host.rofl models/lang/js/lifecycle.rofl` to
   `@rules/js.files` and ask `used_after_death_at`, `leaks_at` (`once` or
   `accumulates`), `leak_unknown_at`, `no_shutdown_at`, `outlives_stop_at`,
   `overwrites_at`. Six relations of behaviour moved into their worlds under
   new names: `suspend_at` → `suspends[execution]`, `hidden_call_pos` →
   `hidden_call[execution]`, `transfer_site` → `transfers[execution]`,
   `param_default` → `fallback[execution]`, `eff_coerced` →
   `coerces[execution]`, `narrows_at` → `narrows[type]`. A question that named
   the old ones must use the new.
11. **The heap at its peak, by part** (#219): `peak:` on stderr of `rofl load`
   and `rofl ask` where the heap passed a gigabyte, the six largest parts
   first; `peak_bytes[profile]`, `peak_rule[profile]` and `bytes[profile]` for
   a rule that reads them.
12. **A world kept by 1.5.1 is computed again once**: the kept worlds are named
   by the engine binary, and the volume format moved (`ROFL-VOLUME-8`,
   `ROFL-OVERLAY-4`).

## What changed since 1.5.1

**The kept world and the edit**

- **#149, #151, #152, #145** An edit no longer reads and writes again what the
  world holds; taking an 8 048-fact file out of vscode 250 kept: 11.5 → 2.9 s;
  the tenth file added in a row 13.0 → 4.3 s.
- **#155, #211** A full evaluation keeps what nothing touched since the last
  whole one, a threshold, a well-founded world's decided part and what does
  not read `derived_by` too: 173 of 197 two-stage worlds keep the lower stage.
- **#156** Each edit is kept over the edit before it: a 402-fact edit writes
  1.1 MB where the eighth in a row wrote 46 MB.
- **#157, #158** A `function` or a `tree` declared into an evaluated world is
  an addition by delta: additions by delta 66% → 94% (addcheck).
- **#180** Loading a whole model by delta reads each new rule once: 1.6–1.9×
  the whole evaluation → 31.5 s against 29.7 s at vscode 250.
- **#213** A delta in a world with holes: what the holes may move is evaluated
  again after the rest, not the whole world.
- **#215** A one-fact retraction the one-fact delta refuses goes by the set's
  pass: worlds evaluated again 37% → 5%; three defects of the set's pass fixed.
- **#223** A full pass keeps a reader of the shrugs or firings of a kept
  relation: worlds whose upper stage evaluated a lower relation again 17 → 15.
- **#225** Kept worlds green after Babel left: every JS edit of a kept world
  was computed anew; now it goes by delta again, and a world kept whole over
  an overlay removes the volumes set aside under it.
- **#224** Volumes by default for `rofl ask` and `rofl why` (above).
- **#195** A reheated volume answers `why` byte for byte as before cooling.

**Speed and memory of the engine**

- **#212** Profile iterations 31–37: about half the instructions of an
  evaluation.
- **#214** Memory forecast from the rules, then built: −210 MB peak at 250
  files.
- **#206** The kernel's own program profiled; the quadratic it found in
  safety.rofl is fixed.
- **#178** The code's facts reach the engine in chunks of at most 32 MB: 700
  vscode files peak at 2.8 GB of Node instead of 4.4 GB.
- **#218** A probe bound at a key from a table of constants reads by the index
  with the most keys: 227 256 798 rows read → 63 258 for the same 9 732
  answers (100 vscode files).
- **#219** The heap at its peak, by part (above); heights in a flat array.
- **#185** Measured, not built: a fact-level cone is 70–72% of the relation
  cone on the JS model.

**The notebook**

- **#183** Cells evaluate in a fork of the Rust engine's world, not in a
  TypeScript copy; answers, whys and pictures byte for byte the same.
- **#171** Cells are cut by the Rust reader's sentence spans.
- **#154** A notebook evaluates only the cone of what its lines ask.
- **#216** Seven findings of the notebook kernel on the Rust path, open (see
  *Known gaps*).

**The JS model**

- **#128** `fs.promises`, `process.env` reads and writes, calls short of their
  callee.
- **#131, #140** A `Map` read sees the puts before it, through calls, in class
  fields and for the walks; `this` in a parent reaches a subclass's override.
- **#132** A call of a member the receiver has not got:
  `missing_member_call[audit]`, `member_unknown[audit]`.
- **#177** Six silent holes made loud: unresolved calls, calls through an
  untraced key, a parameter handed several functions, `require.main`.
- **#192, #199, #205, #207, #220** The roles layer, oxc the only scanner,
  Babel removed (above); the coverage matrix that counted Babel's kinds is
  cut.
- **#222** The `[lifecycle]` world: use after death, leaks, a process with no
  stop, a write overwritten before it is read (above).

**The engine's own code**

- **#150, #197** A model of the engine (`npm run engine`,
  `models/engine/parts.rofl.md`, `blast.rofl.md`): its parts, glossary, call
  paths and what a change touches.
- **#159, #165–#176, #179, #181, #182, #187, #188** Refactoring by metrics:
  `Eval` 265 → 95 fields, the long functions split, one SCC, one readers cone,

**Docs, CI, ledger**

- **#147, #148** docs/cli.md, *A corpus larger than one heap*; a corpus as

- **#153, #209** The guide: what is new, whynot's nearest failure, the memory

- **#190** CI runs `cargo clippy -- -D warnings` on every push; the planted

- **#226** The planted faults green again: `npm run test:agg:breaks` had 49

## Known gaps

- **Not every rule of the JS model reads the roles yet**: the rest read oxc's
  raw tree through `models/lang/js/oxc-to-code.rofl` (w_js_model_on_roles,
  open).
- **Volumes are not cooled** (#224): every worker stays on the heap, so a
  corpus larger than one heap still does not fit; an edited file computes the
  volumes anew, not by delta.
- **The notebook layer keeps its own caches by whole texts** (#216): one edit
  rescans and re-evaluates every file; a dropped kernel leaves its `rofl serve`
  sessions open (+36 MB a switch); with no Rust binary it runs on TypeScript
  without a word; the model is loaded twice; the phrase vocabulary is read
  again per cell; the first query carries the model back into TypeScript.
- **Nothing was measured at the reference scale** (11 100 files); the largest
  worlds here are vscode 250 and 700. `npm run bench` was not run for this
  release.
- 1.5's gaps stand otherwise: Windows has no check that runs, `rofl` costs
  25–50 ms of Node in front of the engine, red as root in cloud containers.
