# ROFL 1.1 — release notes

Since `rofl-nb-1.0.5` (origin/main dcfeb5e, 2026-09-30): about 370 commits on
`core-aggregations` and 343 new findings in `facts/findings.rofl`. Every number
below is quoted from the finding named beside it. Unless a line says otherwise,
it was measured on the Rust engine, release build.

## What an agent must do differently

1. **Measure on Rust release only.** Use `rofl-eval --bytes` or `rofl-load` from
   `rust/target/release/`. TypeScript is the parity reference up to a bounded
   scale, and its timings decide nothing. A world that uses a Rust-only
   capability, or that is too big for TypeScript, is marked
   `check_opt(W, one_engine, rust)` (f_rust_is_the_engine_ts_is_the_reference).
   The Rust-only capabilities are delta-first plans, provenance on demand,
   incremental addition, the closure answered from its tree, and the structure
   report.
2. **Walls may move.** When a better engine stops somewhere else under the same
   budget, that is expected, not a regression. Do not keep an old cut alive.
   If a world exists to test the stop by budget, lower its budget. If the
   engines then disagree, mark the world Rust-only
   (f_the_owner_settles_walls_promises_and_incremental, point 1).
3. **A broken promise refuses the world.** If a world declares `function`,
   `tree ... closure` or `alias` and the data breaks it, the world is refused,
   and every later question is refused too until the cause is fixed. Treat that
   as a false declaration or bad data, not as an engine fault (point 2;
   f_a_refused_world_stays_refused_and_a_wall_judges_the_promise).
4. **General over subsets.** Build the general mechanism. Incremental addition
   takes facts and rules alike, not a rules-only path for cones (point 3).
5. **Fewer knobs.** CLAUDE.md's knob table is the whole agent-facing set.
   `docs/knobs.md` inventories every other flag and `ROFL_*` variable as an
   oracle, a leftover or a removal. Do not add a knob without removing one.
6. **Pick the mode for the use.** For bulk analysis, declare
   `sealed(provenance)` in the world: the set of facts is the contract, and it
   runs 2.2–3.2x faster. For explanation, keep the default witnessed world
   (f_half_the_world_is_provenance_and_a_fifth_is_the_ancestor_closure).
   Both are supported, and `why` works in both.
7. **Name a question's cone.** Add `asks(R)` facts so that only the rules R
   needs are run. A question about a relation outside the cone is refused.
   Never answer it from a partial world (docs/demand-cones.md).
8. **Cross-file rules go through `[surface]`.** A rule in `rules/js-*.rofl`
   that joins facts of two files must read the other file through the
   `[surface]` book (`rules/js-surface.rofl`). The surface lint
   (`examples/surface/`, `facts/surface-lint.rofl`) flags one that does not.
   `npm run test:split` is the parity gate.
9. **Generated blocks.** CLAUDE.md's command block and knob table come from
   `facts/commands.rofl`. Edit the facts, run `npm run docs`, and check with
   `npm run docs -- --check`.
10. **Removed flags.** Do not pass `--delta-first` (plans are always on),
    `--no-provenance` (declare `sealed(provenance)`), `--eager-provenance`,
    `--unsettled`, `sealed(witness)`, `--unordered` or `--closure`. The
    structure-report flags moved from rofl-eval to rofl-load
    (`--propose-structures`, `--structures-min-rows`; `npm run structures`).
    The npm scripts `ablate`, `dagcheck`, `laddercheck` and `splitcheck` are
    gone.

## Engine

- **Aggregates as one cell engine** (docs/aggregates.md).
  - Body aggregates: `count`, `sum` (with its projection key), `min`, `max`,
    `median`, `quantile`, and `rank` over values or tuples.
  - Lattices: `lattice dist(A, C, min D).`, and join lattices with `union`.
  - Thresholds: `at_least(N, X : body)`, which is monotone and may recurse.
  - Semiring tags: `tropical`, `viterbi`, `trust`, `counting`.
  - Dominance and declared orders: `pareto`, `lex`.
  - English sugar that is exactly its lowering.
  - Widening and narrowing.
  - Integers are bounded at ±2^60, and an overflow is a hole.
  - An aggregate inside a relation cycle is accepted when its data is acyclic.
  - Shortest paths over 3,000 nodes take 0.2 s. Without the lattice they wall
    at 102,202 facts; with it they need 144 (f_a_lattice_cell_is_its_fact).
- **The shrug, the third answer.** It is written
  `shrug(Target, Reason, Meta)` in `[$kernel]`. Its causes are a closed
  vocabulary in `shrug.rofl`. `not` succeeds only on an unentailed fact, and
  `why` explains a shrug down to its roots (f_a_shrug_is_the_third_answer).
- **Labeled unknowns.** An unknown is now a labeled null, and a group is
  decided where every completion agrees, up to 64 regions. A brute-force
  completion oracle found 4 unsound answers, all fixed: 164 questions now
  give 0 unsound answers (f_labeled_unknowns_four_unsound_answers).
- **Delta-first join plans**, always on, Rust only. A firing is solved from
  its news first; the witnesses stay in written order. Sealed runs are
  24–35% faster and default runs 9–23% faster, and probes on self fell from
  4.22 M to 1.92 M, with the state identical
  (f_delta_first_plans_fire_a_rule_from_its_news).
- **Provenance on demand**, Rust only. `derived_by` rows are written only when
  something observes them: the state, a query of `derived_by`, a save, a fork
  or a tick boundary. With nothing observed the world holds 44% fewer facts;
  observed, it holds what an eager world holds
  (f_derived_by_is_written_when_asked). Under `sealed(provenance)`, `why`
  re-solves the rules with the head bound, and whycheck finds 0 differences
  (f_under_the_seal_a_why_finds_its_witnesses_again_by_solving_the_rules_with_the_head_bound).
- **Relation cones.** `asks(R)` runs only the rules that reach R. Rules that
  can refuse the world join every cone. Asking `hole`, or deriving an ask,
  keeps every rule. On the notebook cones, 35–45% of the rules run, 79–85% of
  the facts are held, and the run takes 63–78% of the time
  (f_a_notebook_cone_is_a_third_of_the_rules_and_four_fifths_of_the_facts_and_its_answers_need_a_fifth_of_a_percent).
  A soundness sweep fixed 56 wrong asks out of 786
  (f_the_relation_cone_is_sound_where_a_rule_reads_what_no_premise_names).
- **Demand: cycles and tabling**, both engines.
  - A cyclic call iterates to its fixpoint, and a completed call is tabled.
    Open calls in one component iterate together.
  - The cut remains only under a negation opened inside the cycle
    (f_a_cycle_fixpoint_ran_away_unbounded_and_recomputed_every_pass,
    f_a_cycle_of_open_calls_iterated_call_by_call).
  - A closed demand reader is now semi-naive: a chain of 8,000 went from
    67.8 s to 0.22 s (f_a_closed_demand_reader_refired_every_round).
  - A question has its own budget and leaves nothing in the world
    (f_a_question_spent_the_world_budget, f_a_question_stored_what_it_unfolded).
- **Declared structures** (docs/data-structures.md).
  - `function ast_name(N, to Name).` is a promise. It is judged after every
    evaluation, per book
    (f_a_function_is_declared_and_its_promise_is_judged_after_every_evaluation).
  - `tree ast_in(P, C) closure ast_within.` lowers to the two closure rules.
    On Rust, both sealed and witnessed worlds answer the closure from the
    forest: no closure row is stored, and `why` is rebuilt from the parent
    chain.
  - In witnessed worlds, observed, that is 19–22% fewer facts and 15–30%
    shorter evaluation; unobserved, 34–39% fewer facts
    (f_the_witnessed_world_answers_a_declared_closure_from_its_tree).
  - `alias` is proposed by the report, not built.
  - The detection report (`npm run structures`) proposes the forest, the
    closure and aliases on all four corpora
    (f_the_engine_proposes_a_forest_a_closure_and_aliases_on_all_four_corpora).
- **Incremental addition**, Rust only. rofl-serve's `assert` and `load` on an
  evaluated session add facts and rules as a delta, level by level, beside the
  retraction deltas. A fall-back to full evaluation always states its reason.
  - mcp: 37 facts in 1.2 s against 4.6 s fresh; 34 rules in 1.55 s against
    3.01 s. 81% of 176 worlds go by delta.
  - About 2,500 random additions and a differential found 7 defects, all fixed
    (f_an_evaluated_world_takes_facts_and_rules_by_delta,
    f_the_addition_differential_found_four_defects_of_the_paths_it_stands_on).
- **Walls machinery removed.** Written order under a caller wall, the
  near-wall re-solve, `closure_unwalled` and its check are gone. The overrun
  fallback stays (f_the_owner_settles_walls_promises_and_incremental).
- **Occurs check.** Unification refuses to bind X to a term that contains X.
  Before, this overflowed the stack in 17 of 1,000 fuzz seeds (world
  `unify_occurs`).
- **One TypeScript evaluator.** `src/aggeval.ts` mirrors `engine.rs` and runs
  every program; `src/engine.ts` and `src/rounds.ts` are deleted
  (f_one_typescript_evaluator_runs_every_program).
- **Speed.**
  - The 40-file seed, default mode: 11.2 s to 5.9 s; sealed, 3.4 s
    (f_the_engines_own_order_is_another_answer_wherever_the_semantics_names_an_order).
  - Seed load: 3,700 ms to 545 ms
    (f_a_seed_load_was_a_value_tree_and_an_interner_probing_runs_of_eighty).
  - A fork is a copy-on-write layer
    (f_a_fork_is_a_layer_and_costs_the_eval_fields_not_the_world).
  - All 389 files of eslint/lib run in 34.7 s with provenance and 19.2 s
    without. Before, 256 files were killed at 110 s
    (f_the_whole_of_eslint_lib_fits_in_one_world_in_half_a_minute_where_it_hit_the_wall_at_two_hundred_files).
- **why and whynot** print a DAG: a node already shown is written
  `K [above]`, the same byte for byte in both engines
  (f_why_is_a_dag_and_a_proof_is_its_distinct_positions).

## The JS model

- **Shape rewrites** (f_costly_rules_are_shapes, docs/optimising-a-world.md).
  - Rule cost sits in a dozen ways of writing a rule. Rewrites s4–s11 are
    applied, with the public facts identical: probes 22.2 M to 18.5 M sealed,
    23.9 M to 19.6 M default.
  - The lint is `examples/shapes/`; its register of excuses is
    `facts/cost-shapes.rofl`.
  - The optimisation loop (f_ten_rounds_of_rewriting_halved_the_js_models_work_with_every_phrased_relation_identical)
    took premise calls at 40 files from 5.80 M to 2.16 M, with every phrased
    relation identical. Four of its rewrites landed; the rest wait in
    `scripts/js_lab/rewrites.diff`.
- **The `[surface]` book**
  (f_the_surface_book_mirrors_what_escapes_and_every_file_alone_equals_the_whole_world,
  docs/surface-split.md).
  - `rules/js-surface.rofl` has 97 clauses and 51 relations: exports by
    path, subscriptions by callee, and escaping nodes mirrored back into
    their relations. 49 rules were rewritten to cross files through it.
  - In world `vscode_surface_split` and `npm run test:split`, each of 14 files
    alone, with the others' surface, equals the whole world fact for fact.
  - The naive cut loses 84 of 184 answers and invents 16.
  - The one public change is a precision gain: a helper that returns its
    parameter now gives each call its own argument.
  - The surface lint is green, with 8 excuses
    (f_the_surface_lint_is_a_foreign_capable_column_read_by_a_local_premise).
- **Path values** (`rules/js-concat.rofl`,
  f_a_string_built_from_parts_is_a_node_with_parts_and_its_text_is_a_term).
  - A string built from parts is a node with parts. Its text is a term
    (`cat`, `join`, `resolve`, `url`, `dirname`, `basename`) that a host
    renders.
  - It is bounded: at most 16 texts, depth 3.
  - At 500 vscode files: values 248 to 614, evaluation +15%.
- **Exported constants cross files.** `export const PORT = 8080` reaches its
  uses in other modules (f_an_exported_constant_did_not_cross_files).
- **Decorators** run at definition time and are no longer filed under the
  method they decorate
  (f_a_decorator_runs_at_definition_and_the_effect_layer_filed_it_under_the_decorated_method).

## Tooling

- **Scanner.**
  - A file the decorators plugin refuses is parsed again with
    decorators-legacy. On vscode that took the failures from 893 of 4,243
    files to 1.
  - Node id prefixes are 64-bit, and a colliding prefix or a file scanned
    twice is refused in words
    (f_a_node_id_prefix_of_thirty_two_bits_merged_two_files).
- **New scripts:**
  - `npm run whycheck`: why, why all, whynot and excise from both binaries,
    compared with `src/api.ts` byte for byte.
  - `test:agg` and `test:agg:breaks`: planted faults in one `--features
    breaks` build.
  - `test:fast`: the `fast` cargo profile.
  - `test:split` and `structures`.
- **`npm test` choices:** `npm test -- --engine rust|ts` checks one engine,
  and `--changed[=REF]` picks the engine from the tree's changes.
- **The knob audit.** `docs/knobs.md`, and the generated knob table in
  CLAUDE.md (f_the_knob_audit_proposes_removals).
- **A readable why in the notebook.**
  - A why of a value first prints the steps the value took, one line each:
    file:line, the code, and the hop (`across files:`, `exported`,
    `argument I of f()`).
  - Under them comes the proof, with side conditions counted.
  - `npm run nb -- F --all` prints every answer and every proof whole, as
    before. `--json` carries chain, brief and why (docs/md-world.md).
- **The vscode question.** `examples/vscode/` holds the side-effect question
  (`side-effects.rofl` and its notebook) and the `mini/` and `split/`
  corpora. `scripts/vscode_corpus.ts` builds subset S, and
  `scripts/vscode_curve.ts` measures one point.

### The vscode measurement

From f_the_side_effect_question_answers_vscode_in_its_cone_and_walls_on_memory_everywhere_else.
The corpus is 4,243 files. The walls were raised for the run (space 4e7,
budget 4e9); the default space wall falls before 250 files.

- **The question's sealed cone answers everything:** 700 sites and 9,538
  values, in 305 s of evaluation plus 110 s of load, at 15.2 GB.
- **The full sealed world and the witnessed cone** do not fit in 21 GB. At
  2,000 files they take 10.4 and 9.8 GB.
- **Growth:** time grows about as files^1.07 in the cone. A held fact costs
  about 3.6 KB.
- **The wall is memory.** `asserted_by` is 26% of the cone, the AST 25%, and
  the flow under 5%.
- **Values grow about as files^2**, because returns are context-insensitive.

## The surface driver

Built as item 4 of docs/surface-split.md (section 7), `runtime/split.ts` over
rofl-serve
(f_the_driver_answers_from_core_and_surface_and_the_subscription_closure_is_the_cost).

- **A volume** is a fork of the evaluated core holding one file's facts and
  the `[surface]` facts it subscribes to, added by delta. After it evaluates,
  it publishes its new `[surface]` facts and is cooled by book: `[code]`,
  `[flow]` and `[main]` go to a signed volume file, and the surface stays.
  The engine side is `Session::cool_books` and rofl-serve `cool` with `books`.
  A reheat goes by delta.
- **Subscription by key.** A surface fact's key is its first argument. A
  volume reads the keys it owns and the names its facts carry, and is
  evaluated again only when one of those keys moves.
- **Phases close the ingest-order hazard.** A relation's phase is the most
  negations or aggregates over the surface on a path to it. A phase is
  published only once the phases below are quiescent, so each negation reads a
  complete surface and a withdrawal inside a phase turns the gate red. The JS
  model has 4 phases.
- **The resident world** holds every publication. The answers are asked there.
  A why asked there lifts the volumes that published a surface axiom, until
  the proof rests on base facts, then cools them again.
- **How an agent runs it:**
  - `npm run test:split` runs the 14-file gate by hand-loop and through the
    driver, in both orders. Planted breaks `early`, `narrow` and `nophase`
    must turn it red.
  - `node --experimental-strip-types scripts/vscode_curve.ts DIR N split`
    runs the vscode question through the driver.
- **Measured, vscode subset S at 500 files:**
  - The answers are exactly the whole world's: 248 values, 67 sites, 341 keys.
  - It is not yet an economy: 6,335 s against 40 s for the cone world, with
    2.0 GB peak against 2.5 GB.
  - The cost is the subscription closure. A volume reads 14 k surface facts on
    average, 10% of the surface. On 14 files, 6 of the 29 whys match the whole
    world's text; every one is a valid proof there.
  - 1,000 and 4,243 files were not run.
- **The parser now reads the escapes the renderer writes.** Strings accept
  `\b`, `\f` and `\u0000`–`\u001f`, in both engines. A scanned string
  holding a control character could not be read back before.

## Known gaps

- **Context sensitivity is not built.** Returns are context-insensitive, so
  path helpers give every caller the union of their values. On vscode that
  makes the values grow about as files^2: 19 values at one
  `mkdir(dirname(..))`. This blocks asking for 500–800 values with precision
  (work item w_js_call_site_context).
- **Host strings stay in core.** 276 k string facts at 4,243 files carry no
  node id, so they cannot go into a volume (docs/surface-split.md, item 5).
- **The surface driver is correct but not yet cheap.** It is 140 times the
  whole cone world at 500 files. The next steps are each bounded: subscribe
  only to keys a rule can join on, using the lint's foreign-capable columns;
  re-evaluate only when such a key moves; keep volumes hot through a round;
  cool by retraction so a why costs only the lift (docs/surface-split.md,
  section 7).
- **A why through the driver** is a valid proof but not always the whole
  world's text: where a fact has several derivations, the smaller world picks
  another least witness.
- **Kept and whole worlds order a proof's premises differently**
  (f_the_layers_why_probe_named_a_node_id_of_the_old_width). Whether they must
  match or only hold the same facts is the owner's decision, so
  `test:nb:product`'s why-guard stays red until then.
- **Incremental addition.** Only 23% of sealed worlds go by delta. Some cases
  still fall back to full evaluation (w_add_full_reasons). Some deltas cost
  more than a fresh run: an aggregate sealed again whole, news at a premise
  no plan starts from, a forest rebuilt whole (w_add_delta_cost).
- **Retraction and the tree.** Retracting an edge of a tree whose closure is
  answered from the tree is a full evaluation.
- **Labeled unknowns** are sound but incomplete. Some groups shrug where every
  completion agrees, and holistic aggregates are never decided by regions.
- **asks.** A derived ask is not honoured (it keeps every rule), and
  fact-level demand is not built (w_cmp_demand_patterns).
- **Model gaps.**
  - `new` and `extends` of an imported class do not cross files
    (w_js_new_of_an_imported_class).
  - DI-injected receivers resolve nothing.
  - Python ids are still 32-bit.
- **A why at corpus scale** runs to 200–1,100 lines; the chain summary is the
  readable part. A snapshot of a corpus world costs more memory than the
  machine has
  (f_a_snapshot_of_a_corpus_world_costs_more_than_the_machine).

  and one side-effect question, with 500–800 answers, each with a readable
  why, on Rust within a stated time and memory. Fact-level demand, volumes
  resident only where the cone reaches, the surface driver and context
  sensitivity are the cuts.

  ships. The owner runs it after this release.
