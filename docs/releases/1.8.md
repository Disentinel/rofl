# ROFL 1.8 — release notes (unreleased)

Since `rofl-nb-1.7.0` (2026-11-15). Being written as the pull requests land; every line names the PRs that made it.
The 1.7 notes are kept in docs/releases/1.7.md.

## What changed since 1.7.0

**The JS model: how much of a program it gives a value**

A read of a name or a call is *covered* when the model gives it a value: a named one (a node, a literal, an input,
an instance, a global) or an open one (`may_be(E, open, W)`: a value the model does not compute, made at W).
A read or a call with no value at all is *silent*, and a question over it answered short without saying so.
Measured over five public JS projects, all their source files and no tests (`scripts/vscode_corpus.ts corpus`),
Rust release build:

| project (files) | reads 1.7 | reads now | calls 1.7 | calls now |
|---|---|---|---|---|
| express (7) | 72% | 99.7% | 57% | 99.5% |
| axios (83) | 75% | 98.8% | 59% | 97.4% |
| vue core (283) | 95% | 99.4% | 90% | 99.5% |
| three.js (932) | 94.5% | 98.5% | 81.7% | 93.1% |
| react, first 800 of 1613 | — | 98.1% | — | 97.8% |

- **#283** Patterns on the left of `=` and in `catch`, what a call runs (callbacks, executors, `f.call`), what a host
  member returns and puts (`find`, `map`, `push`, `Object.entries`, …), and the open value: an operator, `x++`,
  `x += v`, a host member no table values, a call of a parameter.
- **#287** vue core went past 10 GB on #283: a for-in key used as a key again is open, and two joins through
  `may_be_node` are read once. vue core 48 s, 1.8 GB.
- **#288** Silence had few roots: a name nothing declares is the global of that name (`may_be(E, global, Name)`);
  a default import carries every kind; an enum is exported; a member of a parameter or a literal, `.length`, a catch
  around a call, `arguments`, a walk of what the model does not keep and `new f()` are open. The scanner reads JSX in
  a `.js` file. Finding `f_silence_has_few_roots_and_they_close`.

What still costs: vscode 250 `side_effect_value` 23 s on 1.7, 57 s now, the same 10 answers; three.js 188 s and
6.3 GB; the whole of react ran out of memory on a 15 GB machine, and the engine said so.

## Known gaps

- A member of a known object at a key nothing writes (`const { Axios } = axios`) is still silent.
- What `new f()` returns is open, not carried: carried, three.js's constructors met in one function from thousands
  of calls and the run went past ten minutes.
