# ROFL 1.3 — release notes

Since `rofl-nb-1.2.0` (e599260, 2026-10-11): PRs #22–#50. Every line names the
PR that made it; what an agent must do differently comes first.

## What an agent must do differently

1. **Notebooks never fall back to TypeScript.** A run with `ROFL_NB_LIMIT` or
   `ROFL_NB_MEMORY` and a notebook with `excise` stay on Rust: `rofl serve`
   takes a clock and heap limit on any request, and `excise` forks the Rust
   session (#23). Item 2 of 1.2's list no longer has exceptions.
2. **Declare an alias instead of storing a projection.**
   `alias ast_in(P, C) is ast_child(P, _, _, C).` reads its source and, on
   Rust where no witness is kept, stores no row (#48, docs/data-structures.md).
   The structures report proposes aliases and no longer proposes what is
   declared.
3. **A name written once inside a negation is refused** at load on both
   engines: bind it or write `_` (#38).
4. **Watch stderr for the rule that blows up.** `rofl load` and `rofl serve`
   name the rule and premise that has read 50 M rows and a quarter of all
   reads, with its widest read and bound values (#31,
   docs/optimising-a-world.md).
5. **`whynot` reads differently.** Over a corpus it answers a table, a row per
   file and where each rule stopped in it (#33); every walk starts from what the
   question binds, and a premise with more than 16 matches says how many it
   left (#41). Both engines give the same text.
6. **Walls moved again.** Walled worlds are Rust-only where the engines now
   stop in different places (#25, #44), as the owner's principle says.
7. **Measure releases with `npm run bench`** on a quiet machine; one run varies
   about 10%, so compare medians in facts/bench.rofl, never single runs (#22).
8. **Network questions go through rules/net/.** A request reaches a route only
   through name, address, listener and hops (#46); rules/url.rofl is gone, its
   segmenting lives in net-http. Net relations are prefixed where the JS model
   or boot.rofl already owns the name. Config translators (zones, nginx,
   haproxy, k8s, cloud groups) are written on site as scanners, not in this
   tree (#49).
9. **Pictures start from a viewpoint.** An agent asked for a picture picks one
   of sixty in `rofl:visual/viewpoints.rofl.md` and maps it onto the graph
   words (#50, docs/schemas.md, guide/AGENTS.md).

## New

- **Kept and resumed evaluation** (Rust, docs/staged-evaluation.md):
  - a stop by budget is a continuation, `Session::resume`; 3119 resumes over
    90 worlds each equal the whole run (#24);
  - a kept world opens mapped, `Session::keep_volume` / `open_volume`: 250
    vscode files open in 0.6 s instead of 9.2 s (#27);
  - a volume keeps the place an evaluation stopped and another process goes
    on; keeping 250 files costs about 2 s instead of 16 s (#29);
  - all of vscode (4308 files) reaches its fixpoint in 14 pieces of about
    90 s, `scripts/vscode_pieces.ts` (#29, #30);
  - two stages equal the whole on every world that splits, and dominance and
    join lattices open evaluated (#34, `scripts/addcheck.ts`);
  - the stage planner, `scripts/stage_plan.ts FACTS LIMIT_MB [--run]
    [--check]`, keeps import rings whole and is checked by
    rules/stage-plan.rofl; 100 vscode files in 4 stages run in 49 s instead
    of 87 s (#43); a stage's own memory 131/335/399/351 →
    138/286/260/218 MB (#47).
- **Cheaper additions**: an addition fires on what it adds, so negations,
  closure readers, citers and promises no longer read the whole world (#26);
  aggregates reseal by key and forests extend (#36); a late or unsafe rule no
  longer evaluates an addition again (#45).
- **Faster witnessed worlds** (vscode 250 files, Rust release):
  - peak 1.56 → 1.02 GB, evaluation 41 → 28 s (#25);
  - `asserted_by` written only when read: peak 1.02 → 0.79 GB (#28);
  - a round's level split over threads, answered as one thread (#37);
  - a rule that is not recursive fires once: witnessed 21.95 → 18.1 s, cone
    18.0 → 15.5 s, an ask added to a kept world 569 → 198 ms (#44);
  - aliases: cone facts −12%, peak rows −24%, peak RSS 687 → 600 MB (#48).
- **JS model**: a name is looked up from the scope it is read in (#32); rules
  that worked by spelling follow value and scope, and cross-file reads go
  through the surface (#35); an import finds its file by name (#39); slow
  lookups rewritten so whole vscode answers (#30). The relations
  `shadowed_by`, `shadowed_by_param`, `hidden_at`, `param_hidden` and
  `param_bound_in` are gone.
- **Service graph**: a `fetch` reaches its Express handler as `calls[code]`
  (rules/js-fetch, js-express, js-service, examples/services) (#40), through
  the net library of eight packs (#46).
- **VS Code pictures drawn as a schema** instead of Cytoscape: frames that
  open, notes, a line's contract, per-frame layouts; matrix, timeline and
  quadrant pictures; ROFL draws itself (#50).
- **CI** builds the engine and the VSIX on main and release tags only, not on
  every branch push (#42).

## Install

Pick the VSIX for your platform (`rofl-0.4.0-<platform>.vsix`: linux-x64,
linux-arm64, darwin-x64, darwin-arm64, win32-x64), with VS Code 1.101+:

    code --install-extension rofl-0.4.0-darwin-arm64.vsix

The command line, with Node 22+: `npm install -g ./rofl-nb-1.3.0.tgz`. The
engine alone: `rofl-<platform>` (chmod +x on macOS and Linux).

## Known gaps

- A write below a volume's mark copies a whole mapped column, so a stage
  overshoots its planned memory; an upper stage evaluated again by the
  addition path evaluates the lower one too (docs/staged-evaluation.md).
- The net library walks tcp only; v4-in-v6 addresses and zone ids do not
  read; names are compared as written (#46).
- The JS model reads no nested or rest pattern in a parameter and no lodash
  `assign`/`extend`.
