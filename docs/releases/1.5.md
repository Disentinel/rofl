# ROFL 1.5 — release notes

Since `rofl-nb-1.4.0` (c981587e, 2026-10-22): PRs #89–#126 in 1.5.0, then
1.5.1. Every line names the PR that made it; the install comes first, then
what an agent must do differently. The 1.4 notes are kept in
docs/releases/1.4.md, and their known gaps stand except where a line here says
one is closed.

## 1.5.1

- **A leaner `@grafema/rofl`**: 312 files and 6.9 MB unpacked (1.58 MB packed)
  in 1.5.0, 214 files and 3.9 MB (0.97 MB packed) now. Out: the TypeScript
  sources beside their JavaScript, the library's second copy of its JavaScript
  (the exports now name the commands' own `src/api.js` and `runtime/port.js`;
  `dist/` keeps the `.d.ts` files), the source maps, and the editor's modules
  (`vscode/`), which ship in the VSIX alone. The JS model, the commands, the
  library and its types are whole; `npm run test:npm` now also checks that
  every path the exports name is in the package, `@grafema/rofl/port`
  imports, and a TypeScript project gets the types.
- **The release is rehearsed on main** (docs/npm.md): the release job's
  publishing is `scripts/release_publish.sh`, and the `release-dry` job runs it
  with `--dry-run` on every push to main over that run's artifacts. Its first
  run found that `npm publish npm-dist/<file>.tgz` is read by npm as a GitHub
  repository: the first publish by CI would have failed. 1.5.0's tag first
  failed on `mkdir out npm`, the tree's own `npm/` (#126); neither line had run
  before a tag.
- **#127** The rounds of one evaluation share its budget: an adapter whose
  answer always asks one more question stops at the budget;
  guide/ADAPTERS.md, for authors of adapter books.
- **The npm packages are staged by the release job and approved by the
  owner** (docs/npm.md, *Each release: what the owner clicks*): the job runs
  `npm stage publish` (npm 12) on each, platforms first, signed in by trusted
  publishing (OIDC, provenance); the owner approves the six on npmjs.com in the
  same order. The 1.5.1 tag's first run made the GitHub release and then
  stopped at the first `npm publish` with ENEEDAUTH: npm's sign-in had failed
  and npm does not say why. Now `scripts/npm_oidc.ts` tries the sign-in for
  each package before anything is published and says what the registry
  answered, npm runs with `--loglevel verbose`, the sign-in is rehearsed on
  main and on pull requests, and the causes are in docs/npm.md, *When npm says
  ENEEDAUTH*. A re-run of the tag uploads to the GitHub release already there
  instead of failing on it. 1.5.0 was published by hand.

## Install

ROFL is on npm as **`@grafema/rofl`** (#112). The npm name `rofl` belongs to
someone else's package; 1.4's README told readers to install it, and that line
is gone.

    npm i -g @grafema/rofl                 # rofl, rofl-nb, rofl-lsp; Node 22+
    npx @grafema/rofl ask 'reaches(a, X)' boot.rofl world.rofl
    npm i -g @grafema/rofl@latest          # later: the newest release

- `rofl` is the native engine. It comes from a package of its own per
  platform, `@grafema/rofl-<os>-<cpu>` for linux-x64, linux-arm64, darwin-x64,
  darwin-arm64 and win32-x64, and npm downloads only this machine's. There is
  no TypeScript fallback: with no engine for the platform, or one of another
  version, `rofl` exits 127 and names the package to install.
- **Coming from the 1.4 tarball:** `npm uninstall -g rofl-nb` first. Both
  install `rofl-nb` and `rofl-lsp`, and npm refuses the second with EEXIST,
  leaving nothing half-installed.
- **The GitHub release no longer carries `rofl-nb-<version>.tgz`**, nor the npm
  tarballs. It carries the VSIX per platform, the bare engine per platform and
  `SHA256SUMS`. The npm packages are published to the registry, on the dist-tag
  `latest`, by the release job (trusted publishing, no token kept;
  docs/npm.md says what the owner sets up once).
- The VSIX, with VS Code 1.101+, as before:
  `code --install-extension rofl-1.5.0-darwin-arm64.vsix`.

## What an agent must do differently

1. **Install from npm and ask from any directory** (#112).
   `rofl ask L @rules/js.files code.rofl` reads the JS model the package
   carries, from any directory: the engine reads `@LIST`, and a `.rofl.md`'s
   vocabulary, from the tree it was installed with when there is none here.
   `rofl scan DIR --out code.rofl` is the package's name for `npm run scan --`,
   and a world that scans for itself names it: `scanner(js, "rofl scan src")`.
   `rofl --version` says the version and the engine binary it runs.
2. **A failed scan answers partial, exit 5** (#112). A world whose scanner
   cannot be started or exits non-zero used to answer as if whole, exit 0,
   with only "the world is not kept: ... named nothing it read" on stderr. Now
   each failure is said on stderr (`a scan failed, so the answers may be short
   of what it would have brought: scan_failed(...)`), an ask's rows end with
   `[partial: a scan failed, its facts are not in the world]`, `--json` says
   `"partial":true`, and the exit is 5. The world still holds `scan_failed`.
3. **A world can want what it does not have** (#98, #106–#111, #113, #115,
   #116, #118, #120, #122, #123; docs/intents.md is the design and the record
   of each phase as built). `want Cap(Args) :- Body.` derives a request, never
   a fact; a capability is declared in an adapter's book; an adapter answers
   with facts in its own book, and with `answered(W)`, `failed(W, Reason)`,
   `outcome_unknown(W)` or `want_held(W, Why)` in main. Kinds: `exec`, `sql`
   (SQLite), `mcp` (stdio and HTTP), `openapi`, `rofl`, and `render` in the web
   workbench. `rofl adapter mcp COMMAND|URL` and `rofl adapter openapi SPEC`
   print a book; a key is named in the book or on the command line
   (`HOW[:NAME]=ENV`) and read from the environment, never written into a fact.
   A `does` want is sent only by `rofl serve`'s `dispatch`, only with a
   `permit(W)` rule, at most once per idempotency key, journalled first. The
   one-shot verbs wait for answers; `rofl serve` can evaluate without waiting
   (`"wait":false`) and collect later (`inbox`). The TypeScript engine checks
   wants but sends none, so the worlds that send are Rust-only.
4. **Build without C or tokio if you need to** (#116, #118): `sql` and `net` are
   cargo features, on by default. `cargo build --no-default-features` builds an
   engine with neither; a want that needs one is held with the reason
   (`want_held(W, "this build has no sql adapter …")`).
5. **A JS rename keeps ids** (#101, #114). A statement keeps its id when a name
   it mentions is renamed, so a rename moves far fewer facts; a file scanned
   again for a kept world keeps the ids of the nodes it matches. Ids on the
   incremental path then depend on the history of edits (the owner's choice:
   they are internal ids, and the answers are the same). `rofl load`,
   `npm test`, bless and whycheck always scan from nothing. Scans written by
   1.4's scanner carry the old ids: scan again.
6. **The kept world is a new format**: see *Format changes*. A 1.4 kept world
   is not opened; it is computed again.

## What changed since 1.4.0

- **#89** `guard_arm` reads as "X is conditional on P" in the sentence form.
- **#90 A why in a sealed world reads by index**: on vscode 250, median 195 ms
  → 10.5 ms, worst 2.7 s → 0.7 s, 40 texts byte-identical.
- **#91** Ledger: a default world keeps every witness (the owner, after a
  recount).
- **#92 A world kept again after an edit is an overlay over its base**
  (`ROFL-OVERLAY-1`), not the whole volume; past ¼ of the base it is written
  whole again. Closes 1.4's gap *a kept world is written whole by each edit*,
  with #99 and #103.
- **#93 The disk wall**: a world larger than `ROFL_CACHE_GB` stops at it, is
  kept, answers partially (exit 5), and goes on from there under a larger cap.
- **#94 An edit by delta pays for the edit in six more places** (planner counts
  and tree rows kept with the volume, promises checked on what a retraction
  made, indexes kept through a sweep, firings retaken only where a premise
  came back, the files that go found directly). `ROFL-VOLUME-4`.
- **#95 A kept world opened again reads only what it needs**: a volume, an
  input file or the engine found whole is noted and read again only when its
  length or change time moves; a far world is no base.
- **#96** Ledger: where an edit stops, what a rename costs, a join through
  constants.
- **#97** A firing's premises are solved a run of partial solutions at a time
  on threads; ledger: the first evaluation runs on one thread.
- **#98** Intents designed (docs/intents.md).
- **#99** The overlay splices swept relations, records ids as runs, and drops
  dead records by a whole evaluation once they pass a quarter.
- **#100 A declared tree's forest is kept in the volume** and built again only
  where an edit reaches. `ROFL-VOLUME-5`.
- **#101** A statement keeps its id when a name it mentions is renamed.
- **#102 The tick journal**: what a world was told and when, kept in its volume;
  `Session::replay(T)` rebuilds a past tick.
- **#103** The overlay writes tree rows, citers and forests by reference and
  leaves out indexes the base lacks.
- **#104** A kept world's forest is published as read, and a volume set aside
  as a base keeps its note.
- **#105** Ledger: files in processes meet by `[surface]` in five rounds.
- **#106** Intents phase 1: want heads, their rows and the load checks, in both
  engines.
- **#107** The overlay's splice finds the kept prefix and suffix by blocks
  (fixes #103's slower keep).
- **#108** Intents phase 2: the `exec` adapter; `reads` wants sent a batch a
  round.
- **#109** Intents phase 3: a scanner and an exec adapter are one runner; the
  storeroom caches both.
- **#110** Intents phase 4: the `sql` adapter on SQLite, templates bound by
  parameters; the engine's first native dependency.
- **#111** Intents phase 5: the `mcp` adapter over stdio; `rofl adapter mcp`.
- **#112 The npm package `@grafema/rofl`**, published from the release job;
  `rofl scan`, `rofl --version`; the engine finds `@LIST` and a vocabulary in the
  tree it was installed with; a failed scan answers partial.
- **#113** Intents phase 6: the `does` dispatcher, `permit` as a rule, an
  append-only journal; an approval cannot be typed into a running world.
- **#114** A file scanned again for a kept world keeps the ids of the nodes it
  matches (`scanners/js_inherit.ts`).
- **#115** Intents phase 7: four scenarios as worlds (`examples/intents/`); the
  `rofl` adapter kind.
- **#116** Intents: the post, a world that does not wait for its adapters;
  `sql` as a cargo feature.
- **#117** An aggregate over what did not change fires on what grew outside it,
  instead of resetting.
- **#118** Intents: OpenAPI books and the `openapi` kind, mcp over HTTP, behind
  the cargo feature `net`.
- **#119** A world stops at a level and takes the merged facts there (`rofl
  serve` `evaluate` with `wall`, `admit`, `evaluate_on`).
- **#120** Intents: HTTP adapters take their keys from the environment; OpenAPI
  in YAML.
- **#121** docs/data-structures.md: a file edited in a kept world rebuilds only
  the trees it touches.
- **#122** Intents: OAuth2 client credentials, an MCP server's 401 followed to
  its token endpoint, keys for `rofl adapter` on the command line.
- **#123** Intents: a screen in the web workbench; a press and a typed field
  come back as facts (`clicked`, `filled`).
- **#125** Intents: the screen as a notebook to open in the web workbench
  (`examples/intents/screen.rofl.md`).

## Format changes

- **The kept volume is `ROFL-VOLUME-5`** (1.4.0 wrote `ROFL-VOLUME-3`; #94 made
  4 and #100 made 5): it carries the planner counts, the tree rows, the forests
  of declared trees and the tick journal (#102). An edit is kept as an overlay,
  `ROFL-OVERLAY-1`, over a base volume beside it (#92). A 1.4 volume is refused
  (`a volume of another format`); the worlds the question verbs keep by
  themselves are named by the engine binary, so a new binary computes its own.
- **The language gains `want` heads** (#106) and the adapter book's relations
  (`adapter`, `capability`, `arg`, `answers`, `query`, `component`,
  `http_auth`, `http_needs`, ...). A clause other than a want head that writes a
  want's rows is refused.
- **The JS model's ids** move on a rename far less (#101); a 1.4 scan loads and
  answers, with the old ids.
- **The snapshot (`--seed`, `rofl serve`) is unchanged.**

## Known gaps

- **Windows has no check that runs.** CI builds and type-checks the engine for
  win32, and the release job builds its binary and packages, but no test runs
  `rofl` on Windows; `npm run test:npm` runs on Linux in CI and was run on macOS
  by hand. On Windows, `rofl` runs the engine as a child (there is no
  `process.execve`): signals are passed on, but a hard kill of `node.exe` may
  leave the engine running (#112).
- **A failed scan marks every answer of its run partial**, not only the answers
  whose cone reads the scan: the cone of a failed scan is not known (#112).
- **`rofl` costs about 25–50 ms in front of the engine** on every call, Node's
  start-up before it execs the engine (#112, *Numbers*).
- **An install from the npm tarballs with no registry** needs
  `npm install --offline`: without it npm asks the registry for the other four
  platforms' engines and retries for minutes (#112, docs/npm.md).
- **Intents not built**: the authorization code flow with a person at a browser
  (PKCE, dynamic client registration; a token got by hand goes in as
  `bearer=ENV`, #122); a cap on batch size, `adapter_auth` and `-- reads:`
  stamps for adapters other than the storeroom's (#108); the TypeScript engine
  sends no want.
- **A kept world's opening still costs the world in places** (#95, #100, #104):
  `heights_where_head` (about 8% of an edit), `absorb` (about 4%), a planner
  count missing from the volume, the premise tags and names checked whole at
  open.
- **A sealed world takes an assert by evaluating again whole**, so files in
  processes meeting by `[surface]` re-evaluate each round (#105).
- **Planted faults `scan_previous_ignored` and `scan_inherited_answers_fresh`**
  were not seen to fail when registered (#114).
- **Red as root**: `kept` `an_unwritable_cache_still_answers` and `keep_check`'s
  chmod-000 case fail when the tests run as root (the cloud containers), on
  main too (f_the_unwritable_cache_case_is_red_as_root).
