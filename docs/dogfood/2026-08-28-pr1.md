# Dogfood log — PR1, inquiry kernel (2026-08-28)

The method applied to building the method. Session: implementing the Phase 1
inquiry kernel (rules/inquiry/, examples/atlas-launch/,
runtime/report.ts, test/inquiry.test.ts). Findings recorded per the
learning-loop discipline: each is either already a rule/test or names the
rule/test it should become.

## What worked

**1. The perspective discipline mapped 1:1 onto kernel mechanics — zero
enforcement code.** `[obs]` journal + `authority(obs, runtime)` +
who-attributed loads gave the "LLM reasoning is not evidence" invariant as a
`forged[audit]` derivation; explicit head perspectives auto-emitted
`bridge_decl`, so no `leak[audit]` plumbing was needed. Every §20 invariant
implemented in this PR is a rule or a boot audit, not host code.

**2. The roadmap's Phase 1 test list translated nearly line-per-test.**
Framing the checklist as obligations *before* writing rules surfaced the one
under-specified point — should an ambiguous claim get a `verify` intent? —
as an explicit design decision (clarify precedes verify), documented in the
rule comment instead of buried in behavior.

**3. `excise` is the mutation-testing primitive for free.** Roadmap §18's
"Evidence Removal → full GO disappears" is one API call: excising
`refutes[obs](chat_note_17, …)` diffs away `no_go` AND reopens the claim
for verification. The blast-radius diff *is* the certificate regression test.

**4. Explicit-unknown dissolved.** The roadmap wanted `epistemic_state(C,
unknown)` asserted by hand for fear of negation deriving falsehood. With
claims declared in the frame, `unknown :- claim, not supported, not refuted`
derives *unknownness*, not falsehood — the invariant lives in `refuted`
requiring a journal entry. One less hand-maintained fact kind.

**5. Test-first caught a real bug before it existed.** First instinct for
`resolved_obligation` was `supported` alone; writing the contested test
first showed that would mark a contested claim resolved and silence
`discriminate`. The shipped rule carries `not refuted`.

## What bit, or will bite

**1. The forged audit is opt-in at the kernel level.** A load *without*
`who` emits no `asserted_by`, so `forged[audit]` never sees it: the audit
covers only asserters that identify themselves. Consequence for Phase 2
admission: the runtime MUST refuse to admit `[obs]` facts from an
unattributed load — anonymity must not be a bypass. This needs a rule and a
regression test in the admission layer (`admission.mjs` contract), not just
this note.

**2. File layout is constrained by the kernel grep test.** Any domain code
in `src/` fails CI on vocabulary (by design). `scanners/` and `runtime/`
exist because of it. Lesson generalized: read the enforcement tests before
choosing structure; the constraint was documented but only operative once
`scripts/kernel_grep.ts` was read.

**3. Untested edge: negating a never-populated EDB relation.** The fixture
declares at least one fact of every negated frame relation (`ambiguous`,
`requires_authority`). A minimal frame with none — e.g. no ambiguous claims
at all — leaves that relation without `edb()` registration, and its stratum
assignment exists only through the dep graph. Worked here; needs a dedicated
kernel test with a frame omitting each optional relation in turn (PR2).

**4. Intent identity as a tuple held up.** No gensym pressure appeared
anywhere in Phase 1; `(kind, inquiry, target)` deduplicates for free in the
fact store. The runtime execution-id split (roadmap §4.6) can wait.
