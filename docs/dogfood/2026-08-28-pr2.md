# Dogfood log — PR2–PR4 scope in one pass (2026-08-28)

Session: agent execution contract (schema, admission), bounded tick loop
(scheduler, checkpoints), production-readiness decision pack with mutation
tests, and the skill seed. Indexed in `facts/findings.rofl`.

## What worked

**1. The schema enforces the evidence invariant by construction.**
`intent-result.json`'s evidence kind enum simply has no `measured` member —
an agent cannot mint measured evidence because the word does not validate.
The strongest enforcement is the one with no code path to argue with.

**2. Excise as the mutation primitive earned its adoption immediately.**
"Evidence removal drops GO" is one call whose diff contains both the lost
certificate and the reopened verify intent. Adopted in the pack tests
(decision taken in-session; reversible — flagged to Vadim).

**3. The frontier needs no state machine.** Candidate intents are derived,
so scheduling top-K and "preserving" the rest costs nothing: the deferred
intents simply re-derive next tick unless the world changed. Roadmap §9.2's
lifecycle states may collapse to just runtime bookkeeping.

## What bit

**1. `excise` does not mutate — it answers "what if".** Three pack tests
written on the assumption that excise removes the fact failed identically;
`retract` is the mutation, excise diffs a scratch store. The test file now
demonstrates both deliberately. (`f_excise_is_counterfactual`, settled.)

**2. Evidence polarity is agent-interpreted at admission.** Admission enters
`supports/refutes` into `[obs]` based on the agent's own assertion state.
The evidence *item* is real (source, content), but its polarity — supports
vs refutes — is agent judgment laundered through the runtime's pen. For
blocking claims a stricter regime may be warranted (human or tool
confirmation of polarity). Open, `demands(decision)` — escalated.
(`f_evidence_polarity_agent_interpreted`.)
