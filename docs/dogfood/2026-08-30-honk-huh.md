# Dogfood log — HONK and HUH against the actual kernel (2026-08-30)

Two example specs arrived (`HONK.md`, `HUH.md`): joke domains, real
engineering load. HONK — one rule set, seven semirings, over a *cyclic*
crafting graph. HUH — why/whynot over a shell pipe. Both are pitched as
tests of kernel sufficiency ("если обёртка выходит толстой — значит, ядро
чего-то не умеет"), so this log answers one question only: **what does the
kernel today actually not do?**

Everything below was measured by running the shapes, not by reading the
source. Probe scripts are throwaway; the numbers are not.

## What already works, and it is the expensive half

**Rules-as-data is done.** `encodeRule` turns every clause into
`premise_lit`/`conclusion_lit` facts and the evaluator reads rules *only*
through `decodeRules`. HONK's whole pitch — "при переключении левая панель
не меняется ни на символ" — is already architecturally true: the rules
live in the store, and the carrier is mentioned nowhere in them. Nothing
needs building for that.

**Content-addressed rule ids carry the weights.** Rule id is
`r` + fnv1a(canonical clause), so tropical costs and Viterbi
probabilities attach from outside as plain facts — `cost(r8326d514, 5).`
— without a character changing in the rules. This is exactly the
separation HONK asks for, and it falls out of an existing decision.

**`why` is already HUH's why-panel.** A four-stage pipe
(`grep`→`awk`→`sort`→bucket) over pre-tokenized log facts gives:

```
s_bucket[main](checkout)  <= r141955e1 @tick 0
  s_sort[main](1,checkout)  <= r4af65fc3 @tick 0
    s_awk[main](1,checkout)  <= r6518c49f @tick 0
      s_grep[main](1)  <= r82171c0f @tick 0
        line[main](1) [axiom]
        status[main](1,404) [axiom]
        404 >= 400 [builtin]
```

Full depth, through the builtins, to the axioms. That is the spec's
why-tree, modulo formatting. HUH's positive direction is free.

**The Boolean column of HONK runs on cyclic data today** — see below.

## Finding 1: the universal quantifier has exactly one working encoding

HONK writes the core rule as
`all(I in Ingredients: craftable(I))`. That is sugar for something, and
*which* something decides whether the demo runs at all. Three encodings,
three different failures, one success:

| encoding | outcome |
|---|---|
| monotone cons-list walk | **99 747 junk facts**, budget dead |
| demand-driven (`L = cons(H,T)` to force unsafety) | diverges on cycles; no tabling |
| negation (`blocked(I) :- ingredient(I,J), not craftable(J)`) | **correctly rejected: unstratified** |
| suffix-indexed monotone walk | **1 ms, 8 facts, correct** |

The naive monotone walk

```
all_craftable(nil).
all_craftable(cons(H, T)) :- craftable(H), all_craftable(T).
```

is range-restricted, so it runs bottom-up — and bottom-up it enumerates
*every list over every craftable item at every length*, not the lists
recipes actually name. 99 747 facts of `cons(coal,cons(coal,cons(coal,…`
before the budget stopped it, and `craftable(plastic)` never got derived.

Forcing it demand-side (`all_craftable(L) :- L = cons(H,T), …`, unsafe by
construction, so the engine unfolds top-down) fails the other way: the
kernel's demand evaluation has **no tabling**, so the mandated petroleum
cycle recurses until `MAX_DEPTH`. HONK's hard requirement — "в графе
должны быть циклы" — targets precisely the evaluation mode that cannot
survive them.

The negation reading is refused, and refused *well*:

```
program rejected: unstratified[main](blocked), unstratified[main](craftable)
unstratified[main](blocked)  <= r25ecbd01 @tick 0
  dep_neg[main](blocked,craftable)  <= rb619e45c @tick 0
  reach[main](craftable,blocked)  <= r6a8b1314 @tick 0
```

What works is indexing the walk by the recipes, so it can only range over
suffixes that exist:

```
suffix(L)      :- recipe(_, L).
suffix(T)      :- suffix(cons(_, T)).
ok(nil).
ok(cons(H, T)) :- suffix(cons(H, T)), craftable(H), ok(T).
craftable(I)   :- recipe(I, L), ok(L).
```

1 ms. 8 `ok` facts. Correct through both petroleum cycles, correct
exclusion of the exit-less `unobtainium ↔ dark_matter` pair, and a full
why-tree down to `raw(crude_oil)`.

**This is the example's real teaching content.** No reader guesses it from
`all(…)`. The gap between the one-line spec and the encoding that survives
a cyclic graph *is* the engineering depth the specs promise — it should be
shown, not hidden behind sugar.

## Finding 2: six of seven semirings have nowhere to live

The value lattice is hard-wired to the powerset of ground facts:
`Store.add` returns present/absent, `conclude` has no annotation slot.
There is no `Evaluation<S>`.

Simulating a semiring in-language does not rescue it. Tropical (min,+) over
the cyclic graph, written the obvious way:

```
cost(I, C) :- step(I, J, W), cost(J, C0), C is C0 + W.
```

→ **74 831 cost facts** in 149 ms, values `10, 100, 1000, 10000, 10002,
10004, …` — every path length enumerated, budget exhausted, no `min`
anywhere. Counting over a cycle is worse: infinite by definition.

So HONK needs a semiring-parameterised evaluator over the same reflected
rules. Note the layering: a semiring interface is *generic*, so `src/` is
where it legally belongs under the kernel grep test — but START.md §8 lists
"aggregation" under **do not build**. Semiring evaluation is generalised
aggregation. **This is a spec amendment, and it must be decided as one.**
The roadmap already anticipates it (Phase 6, "Later Model: Use semiring
annotations") without scoping it.

## Finding 3: the spec's own table is missing a column

⊕ and ⊗ do not determine a semiring evaluation on cyclic data. You also
need `0̄`, `1̄`, and — because HONK *mandates* cycles — a **closure**
operator `a*`.

- Boolean, Polynomial, Best-derivation are ⊕-idempotent → naive Kleene
  iteration terminates.
- Counting (ℕ, +, ×) over a cycle has infinitely many derivation trees.
  It is not "slow"; it is **undefined** without `*`.
- Tropical needs `a* = 0̄` for non-negative weights (or Dijkstra ordering)
  to converge.

HONK's table lists seven rows of ⊕/⊗ and no closure column, so as written
four of the seven columns are ill-specified on exactly the graphs the spec
requires. AAAAA's `ААААА = не сошлось` is the honest *symptom* — but the
other six are supposed to converge, not scream. Worth fixing in the spec
before it is implemented.

## Finding 4: whynot stops after one level — and that is HUH's whole pitch

Measured, on the pipe, for a line that a 503 status dropped at stage one:

```
whynot s_sort[main](4,checkout):
  rule r4af65fc3: s_sort(?N,?P) :- s_awk(?N,?P)
    failed premise: s_awk[main](4,checkout)
```

It names the failing premise and stops. HUH's headline is "**какая именно
стадия** их съела" — which needs recursion into the failing premise until
it bottoms out on base facts or a builtin (`404 <= 499` fails, *there* is
the answer).

LIMITS.md's "whynot is single-step" is about **multi-fact abduction**, a
different axis: recursing the tree is still single-step abduction at each
level. So this is implementable without touching §8, the machinery
(`whynotStruct` + `matchPremise`) is already there, and it is **the
cheapest high-value item on this whole page.** Needs a cycle guard and a
depth budget, nothing more.

## Finding 5: the derivation forest is computed, then thrown away

`Store.support()` accumulates *every* firing signature in `firings`, but
keeps only the **first** structured `Witness`. Three rules concluding
`p(1)`:

```
supportCount: 3
why p(1):
p[main](1)  <= r4d803971 @tick 0
  a[main](1) [axiom]
```

One branch shown. Best-derivation (argmin over trees), Polynomial (which
ores), Counting, and HUH's "which 47 lines" all need the forest.

Good news, and it shrinks the estimate: the hypergraph **is** computed and
retained — the signatures are `ruleId|fact:key|fact:key|…`. Only the
structured form is dropped. `witnesses: Map<string, Witness[]>` is a
few-line change. The real work is the output contract: `why` rendering one
tree is the right *default*, so this needs a forest mode, not a
replacement.

## Finding 6: an unknown relation is silently an empty relation

```
hit(N) :- msg(N, S), contains(S, "404").
```

**Loads clean.** `contains` is not a builtin, so it parses as a relation
with no rules and no facts, and `hit` is silently always empty. `unmoded[audit]`
catches unknown *builtins*; nothing catches a body relation that nothing
can ever populate.

This is not HUH-specific — it is a general trap, and it costs nothing to
audit: `edb`, `concludes` and `premise_pos` are all in the store already,
so `undefined_premise[audit](R, Rel)` is a boot.rofl rule, not kernel code.

Separately, and needing a decision: there are **no string builtins at all**
(and `is` is integer-only — `3 / 2 = 1`, so Viterbi has no carrier either).
A pipe demo whose stages are `grep` and `awk` must therefore push
tokenization into the host. That is architecturally fine — it is what
`scanners/` is for — but it **moves the why-boundary**: `why` then explains
from tokenized facts onward, while HUH's spec tree starts at "grep 4xx
пропустил 47 из 128340". Either add mode-checked string builtins or redraw
the demo's boundary honestly. Do not let it happen by accident.

## Finding 7: the million-line criterion is not reachable

HUH's acceptance list says "накладные расходы честно измерены на логе в
миллион строк". Measured, inserting into one relation:

```
  10000 facts ->     45 ms  (4.5 us/fact)
  50000 facts ->    543 ms  (10.9 us/fact)
 200000 facts ->  22732 ms  (113.7 us/fact)
```

5× the facts cost 12× the time; 4× more cost 42×. The per-relation index
keeps a sorted array and every `add()` does a binary search plus
`Array.splice` — an O(n) memmove, so O(n²) overall. Extrapolating: ~1M
facts in a single relation ≈ **10 minutes**; sharded across six stage
relations ≈ 90 s, before any fixpoint work.

Both numbers break CLAUDE.md's 300-second check budget on their own. The
fix is an index that appends and sorts lazily, or a skip structure — a
contained change, but it must land *before* anyone promises the million-line
figure, not after.

## Verdict

Ranked by "blocks the demo" × "cheap to fix":

1. **Recursive whynot** — HUH's entire selling point, machinery already
   present, no spec conflict. Do this first.
2. **Witness forest** (`Witness[]` + a `why --all` mode) — small, unblocks
   HUH's counting story and three of HONK's columns.
3. **`undefined_premise` audit** — a boot.rofl rule, zero kernel code.
4. **Store index scaling** — contained, gates HUH's own acceptance number.
5. **Semiring evaluator** — the big one, and a **§8 spec amendment first**.
   Needs `0̄/1̄/*`, a convergence test, and a decision on a non-integer
   carrier for Viterbi.
6. **Spec fixes to HONK itself** — add the closure column; replace `all(…)`
   with the suffix-indexed encoding, because that encoding *is* the lesson.

The specs are good. HONK's Boolean column and HUH's why-direction run on
today's kernel, which is more than either spec assumes. What neither spec
priced is that cycles — the thing both correctly insist on — are exactly
what breaks tabling-free demand evaluation and non-idempotent semirings.
