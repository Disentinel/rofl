# Руководство ROFL

ROFL держит модель вашего кода и отвечает на вопросы о ней с доказательством.
Эти страницы — документация для людей: что он отвечает, как спрашивать, как
писать свои правила. Каждый вывод команды в них напечатан самим инструментом
при сборке руководства, а не набран руками, так что вы читаете то, что
действительно работает. Страницы публикуются на
[disentinel.github.io/rofl/guide](https://disentinel.github.io/rofl/guide/)
при каждом слиянии в main.

Английский текст — исходный; перевод идёт за ним с отставанием не больше
недели. Код, команды и их вывод везде остаются английскими: это то, что вы
увидите у себя на экране. Глава, которой ещё нет по-русски, открывается
по-английски и помечена в списке слева как «(en)».

## Что нового

### В main, ещё не в релизе

- **Доказательство останавливается там, где прочитан код.** Модель JS
  сначала превращает дерево oxc каждого файла в более простые факты, её
  леммы. Доказательство в блокноте теперь останавливается на лемме и
  называет её строку, `(a lemma, checkout.js:4)`, а не идёт дальше по
  дереву сканера под ней ([WHAT.md](WHAT.md), «Ответ и его доказательство»).
- **Большие проекты получают полный ответ.** Когда памяти мало, каждый
  рабочий процесс пишет то, что держит, на диск и дальше читает это оттуда.
  О 1 000 файлах VS Code на машине с 15 ГБ версия 1.6 отвечала лишь
  частично; теперь ответ полный, меньше чем за три минуты и с 6,7 ГБ на
  диске.
- **Правка большого сохранённого мира стоит примерно столько, сколько сама
  правка.** В проекте, разделённом по файлам, 1.6 после правки вычисляла
  заново каждый файл; теперь — только изменённые, а то, что они меняют в
  остальных, передаётся туда. На 250 файлах VS Code переименование
  экспортируемой функции обрабатывается за 1,6 с.

### 1.6 (7 ноября 2026)

- Книгу адаптера можно подписать на узле Roflenox, и движок её проверит;
  адаптер `rofl` может спрашивать мир, который обслуживает другой процесс;
  человек входит в сервис адаптера через браузер (`rofl adapter login`); время
  события сводится к одному моменту, в каком бы часовом поясе его ни записали
  ([ADAPTERS.md](ADAPTERS.md)).
- Модель JS говорит, когда код вызывает у объекта член, которого у него нет,
  и читает `Map` в том порядке, в каком записаны вызовы `set`.
- Правка сохранённого мира стоит меньше: на 250 файлах VS Code десятый файл,
  добавленный один за другим, обходится в 4,3 с вместо 13. Каждая правка
  сохраняется поверх предыдущей, поэтому пишет примерно то, что изменила:
  1,1 МБ для файла в 400 фактов там, где восьмая правка подряд раньше
  писала 46 МБ. Мир, который приходится вычислять целиком заново, оставляет
  как есть то, чего с тех пор ничто не коснулось.
- Вопрос вычисляет только то, что ему нужно: первый `rofl ask` над 700
  файлами VS Code занимает 49 с и 2,1 ГБ вместо 104 с и 3,4 ГБ, а блокнот
  запускает только правила, о которых спрашивают его строки.
- Мир больше памяти останавливается, отвечает тем, что есть, как частичным
  ответом (код выхода 5) и говорит об этом; процесс больше не погибает на
  полпути ([ASKING.md](ASKING.md), «Второй вопрос ничего не стоит»).
- `whynot` показывает ближайшее место, где останавливается «нет», — путь, на
  котором осталось меньше всего невыполненных условий; `rofl whynot --all` и
  `rofl-nb --all` печатают все пути, которые он перебрал.
- Модель JS называет больше того, что не смогла проследить: вызовы, которые
  она не разрешила, вызовы по непрослеженному ключу и то, что они могут
  запустить, параметр, в который передают несколько функций; а код под
  `require.main === module` читается как скрипт, если мир так скажет
  ([ASKING.md](ASKING.md), «Чего он не видел»).
- VS Code открывает блокнот прямо с GitHub, в том числе из закрытых
  репозиториев: **ROFL: Open notebook from GitHub…**
  ([QUICKSTART.md](QUICKSTART.md)).
- **Новый сканер JS.** `rofl scan` читает JavaScript и TypeScript через oxc
  на Rust, а модель JS читает слой ролей над его деревом; Babel больше нет.
  Скан, сделанный версией 1.5, не загрузится: просканируйте заново.
- **Большой проект делится по файлам.** `rofl ask` и `rofl why` раздают
  файлы по исполнителю на ядро и объединяют их ответы: 500 файлов VS Code за
  32 с вместо 71 с на четырёх ядрах, ответы те же.
- **Утечки и использование после смерти.** Модель JS говорит, где таймер,
  поток, сервер или дочерний процесс используется после закрытия, никогда не
  закрывается или держит процесс живым без обработчика остановки (docs/cli.md,
  «The lifecycle of a resource»).

### 1.5 (1.5.0 — 24 октября 2026, 1.5.1 — 25 октября)

- **Установка из npm**: `npm install -g @grafema/rofl` ([INSTALL.md](INSTALL.md)).
  npm скачивает движок только для вашей машины. Если у вас стоял 1.4 из
  архива, сначала выполните `npm uninstall -g rofl-nb`. 1.5.1 — тот же
  инструмент, но скачивается 1 МБ вместо 1,6 МБ.
- **Спрашивать о коде можно из любого каталога.** `rofl scan DIR --out code.rofl`
  превращает JavaScript в факты, а `@rules/js.files` находит модель JS,
  которая лежит в пакете; `rofl --version` говорит, какая версия работает
  ([ASKING.md](ASKING.md)).
- **Повторный вопрос после правки стоит дёшево.** Сохранённый мир забирает
  изменённый файл и хранит рядом с прежним миром только то, что изменилось.
  На 250 файлах VS Code правка и вопрос после неё занимают около секунды, а
  тот же вопрос ещё раз — около трети секунды.
- **Неполный ответ так и говорит.** Если сканирование упало или мир вырос
  больше предела кэша (`ROFL_CACHE_GB`), ответ помечен как частичный, а код
  выхода — 5 ([ASKING.md](ASKING.md), «Коды выхода»).
- **Мир может обратиться наружу.** Правило `want` спрашивает программу, базу
  SQLite, MCP-сервер, HTTP API или другой мир ROFL, и ответы приходят
  фактами, которые правила читают как любые другие ([ADAPTERS.md](ADAPTERS.md)).
- Мир, сохранённый версией 1.4, один раз вычисляется заново: формат
  сохранённого мира изменился.
