WTF

A creature's numbers get changed by several things at once, and the order those changes happen in decides the answer. Here is what one creature ends up as, and exactly why in that order.

Magic: the Gathering's continuous-effects rules (CR 613) are a fixpoint with three different ordering mechanisms stacked on it: seven layers, timestamp order inside a layer, and dependency overriding timestamp on top of that — plus state-based actions as a second fixpoint above the whole thing. Only the first is stratification, and only under an encoding that earns it. The numbers below are measured, not asserted.

timestamp decided the colour; struck out is an effect that was overridden.

Two things wanted to change this bear's numbers.

  • Another card on the table says "other Bears you control get +1/+1". It did not start out saying Bears — it said Elves, and a spell rewrote that one word. So now it points at this bear, and the bear is 3/3.
  • A second card says "white creatures you control get +1/+1". The bear was painted white by one card — and then a later spell painted it blue. When two paint jobs land in the same layer, the later one wins. Blue is not white, so that +1/+1 never arrives.

That is the whole answer to "why isn't it 4/4?": one layer, one timestamp, one card that arrived a moment too late. And it is checkable — swap the two timestamps, run it again, and the bear is 4/4.

The same card, copied, sitting right next to it, is 4/4. Nothing about the copy is different except that nobody painted it blue.

Every step names its layer and its timestamp, and every override names what beat it. The whynot query answers the negative form directly: mod73(grizzly, e_honor, 1, 1) fails on co5(grizzly, white), which fails because clob5(grizzly, e_painter) holds — a later setter in the same sublayer. The "what would have to differ" is then executed rather than asserted: the demo swaps the two timestamps, re-evaluates, and prints 3/3 -> 4/4.

When "who got here first" stops being the rule

Dependency overrides timestamp (CR 613.8)

Usually, when two cards want to change the same thing, the one that arrived earlier goes first. Usually.

Three cards are on the table, and all three change what lands are:

  • Urborg (arrived first): "every land is also a Swamp."
  • Yavimaya (arrived second): "every land is also a Forest."
  • Blood Moon (arrived last): "any land that isn't a basic land is a Mountain — and it forgets everything written on it."

Here is the catch. Urborg and Yavimaya are not basic lands. So Blood Moon erases their text. If Blood Moon goes last, they have already done their job and every land is a Swamp and a Forest. If Blood Moon goes first, they never say anything at all.

The rules do not let that be decided by who arrived first. An effect that would wipe out another effect has to be applied before it. So Blood Moon goes first — even though it arrived last. Urborg and Yavimaya do nothing, ever.

Judges have written this down. This tool works it out from the rules, and it gets the same answer.

CR 613.8a: an effect depends on another if they apply in the same layer and applying the other "would change the text or the existence of the first effect, what it applies to, or what it does to any of the things it applies to". CR 305.7 makes setting a land's subtype also strip the abilities from its rules text — so Blood Moon's layer 4 effect removes the abilities that generate Urborg's and Yavimaya's layer 4 effects. Existence clause; both depend on Blood Moon; 613.8b applies it first regardless of timestamps.

None of that is declared in the model. dep_reason/3 derives it, including the counterfactual half: a relation hyp4 holds the state in which only the other effect has been applied, and the two target sets are compared. 613.8b's dependency-loop fallback is loop4, mutual reachability in the dependency graph — a strongly connected component, by transitive closure.

Three ordering mechanisms, and only one is stratification

CR 613 stacks three different orderings, and calling all of them "strata" would be a false claim about the kernel:

  1. The seven layers — a candidate for strata, measured below.
  2. Timestamps inside a layer — not strata. Stratification cannot order anything inside one level at all. bef_ts is one rule over integer timestamps that reads no layer state, and it sits at the bottom.
  3. Dependency overriding timestamp — not strata either. It is a conditional reordering derived from the effects' own semantics. Its own relations do form strata (dep_reason=5 ≤ edep4=6 ≤ eta4=7 ≤ live4=8 ≤ ty4=9), which is a fact about how it is computed — below the layer it reorders, so nothing had to schedule it — not about what it is.

And (1) is not free either

A kernel stratum is a level forced by negation, derived by boot.rofl from the rule dependency graph. An MTG layer is an order the rulebook asserts. The two coincide only where layer N's rules negate on layer N−1's relation, so every boundary in the model is written in one shape: 

lost_N(...) :- <layer N-1>(...), <it was replaced>.
<layer N>   :- <layer N-1>(...), not lost_N(...).

Writing not anyset5(O) instead — a fact about effects — is semantically identical and buys nothing, because it never reads the layer below. Measured on this program, layer 5, both ways:

So the claim "the kernel derived the layer order" is worth exactly as much as the encoding that earns it, and no more.

The four flat ones are reported, not explained away, and each is a fact about the domain rather than a defect in the encoding:

  • ty1→ty3, co1→co3: a text-changing effect rewrites text, never types or colours. ty3(O, T) :- ty1(O, T). is a literal alias — no removal, so no negation to route.
  • printed_ctrl→ct1: a copy effect does not change who controls the object.
  • pt7b→pt7c: layer 7c only adds. It overrides nothing, so no negation exists; the order is still forced, positively — reach(pt7c, pt7b) holds and reach(pt7b, pt7c) does not.

The one place the kernel refused

613.8b's scheduler — "waits to apply until just after all of those effects have been applied" — is a greedy topological sort keyed on timestamp, i.e. a max over a transitive closure. v0 has no aggregation, and the natural encoding puts a negation inside a recursion, which unstratified/1 rejects. Correctly: that program has no least fixpoint. The way through is to compute the closure positively first, then take the maximum with a single negation on top: 

anc4(A, B)  :- edep4(A, B).
anc4(A, B)  :- edep4(A, X), anc4(X, B).

cts4(E, T)  :- lay4(E), eff_ts(E, T).
cts4(E, T)  :- anc4(E, B), eff_ts(B, T).
low4(E, T)  :- cts4(E, T), cts4(E, T2), T2 > T.
eta4(E, T)  :- cts4(E, T), not low4(E, T).

eta4 is the largest timestamp among an effect and its dependency ancestors; sorting by (eta4, timestamp) reproduces the greedy walk exactly. An independent implementation checks that claim on every order the sweep produces.

We tried every order

Counting application orders

If the order matters, the obvious thing to do is try all of them. So the tool shuffles the timestamps inside one layer, every possible way, works the whole board out again each time, and counts how many different answers come out.

One answer from every order means nothing can go wrong there. More than one answer means the board really does depend on which card showed up first — and that is exactly the situation people argue about and judges write rulings for. The tool finds those on its own.

Every permutation of a sublayer's timestamps is a distinct application order. The sweep re-runs the entire layer computation under each and counts distinct final boards — characteristics only, never the intermediate ordering relations, which change by construction.

The rule about erasing effects is the whole reason there is one answer instead of four. CR 613.8 is what collapses an order-dependent configuration into a stable one, and the sweep demonstrates that instead of asserting it. Layer 7c is stable for an unrelated reason — integer addition commutes — and layers 5 and 6 are order-dependent, correctly: those are the ones where the rules really do let the timestamp decide.

One death causes another

State-based actions: a second fixpoint

A creature whose toughness drops to zero dies. But a creature that dies stops doing whatever it was doing — and if what it was doing was keeping another creature big, that one can die too. So you cannot check once. You check, remove, work the whole board out again, and check again, until nothing else dies.

CR 704.5f is a fixpoint above the layer computation: a creature with toughness ≤ 0 leaves the battlefield, which removes the effects its abilities generated, which re-runs all seven layers, which can make another creature lethal. The demo drives it by retracting on_bf/1 and re-evaluating.

Is any of this right?

A program that only checks itself against itself has checked nothing. So the answers here are checked three ways:

  • A second, completely separate program works the same boards out the plain step-by-step way, and gets the same answer — on 42 boards and 41 orderings, with zero disagreements.
  • The official rulebook contains worked examples that state the answer. Two of them are set up on this board, and both come out: 4/6 and 5/8.
  • The Blood Moon case above is a published judge ruling.

Not done: running a real Magic game program. Those are games you play, not calculators you can ask a question, so it would have meant building a whole game inside one. Better to say so than to imply it was checked.

An independent implementation of CR 613 — simulate(), the obvious sequential layer walk in plain TypeScript, with 613.8a's dependency test done by cloning the board and comparing, and 613.8b's scheduler written as the greedy loop the rule describes. It is stricter than the rules file in one respect: it re-evaluates each effect's target set at the moment that effect is applied. Agreement on 42 boards, 41 layer-4 orders, zero disagreements; and it is shown to discriminate rather than rubber-stamp — it sides with the dependency answer against the timestamp-only one, and a changed board breaks the match.
  2. The Comprehensive Rules' own worked examples, which state their answers numerically: CR 613.4d Example 1 must be 4/6, CR 613.5 Example 2 must be 5/8. Both reproduce.

Not run: an actual rules engine. Java is installed on the build machine, but Forge and XMage are interactive game clients with no scriptable "evaluate this board" entry point. Stated rather than implied.

What the encoding assumes, as relations that must be empty

Each of these is a way the model could be quietly wrong, written as a rule rather than a comment, so the test asserts it instead of trusting it: unordered4, cyclic4, intrans4 (the layer 4 order is a strict total order), kill_chain4 (dead4's one-level reading holds), unsound4 (no surviving effect's target set shifts inside its layer), p5_dep/p6_dep/p72_dep (the timestamp-only sublayers have no dependency to miss — an empty over-approximation of 613.8a is a proof the exact relation is empty), and ts_tie (no two effects in one sublayer share a timestamp).

One measured result worth keeping: boot.rofl is load-bearing for this program, not an audit bolted on. Loaded without it there are no stratum/2 facts, every negation rule runs in one final pass, and the answers are wrong — Urborg's dead effect applies and Blood Moon loses. The test pins that too.
